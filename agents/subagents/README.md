# Canonical subagents

One source file per subagent, projected into every harness that has a native
subagent format. Unlike skills — which are plain directories every harness can
read, so they are symlinked — subagent frontmatter is harness-specific. These
files are therefore **translated**, not linked:

```
agents/subagents/<name>.md
        │
        ├── bin/agents_render subagent … claude   ──▶  ~/.claude/agents/<name>.md
        └── bin/agents_render subagent … opencode ──▶  ~/.config/opencode/agents/<name>.md
```

`bin/agents_link all` does the projection; `bin/agents_link --check all` reports
drift. The generated files are **not tracked** — edit the source here and
regenerate. Every generated file carries this as the first body line:

```html
<!-- generated by bin/agents_link from agents/subagents/<name>.md — do not edit -->
```

That header is also the discriminator: `agents_link` prunes generated files whose
source is gone, and leaves any file without the header alone as harness-native.

## Schema

```yaml
---
name: explore             # required; ^[a-z0-9][a-z0-9-]*$; must equal the filename stem
description: <one line>   # required; third-person delegation trigger
tools: [Read, Grep, Glob] # optional; Claude tool vocabulary; omit to inherit every tool
model: inherit            # optional; haiku | sonnet | opus | inherit (default inherit)
permission: read-only     # optional; read-only | safe | full (default safe)
---
Body = the subagent's system prompt, projected verbatim.
```

The frontmatter parser is a **strict subset of YAML**, not a YAML parser: `---`
fences, single-line `key: value` pairs, and inline `[a, b]` lists. Block scalars
(`>-`, `|`), nested maps, continuation lines, unknown keys, and a `name` that
disagrees with the filename are all hard generation errors rather than silent
guesses. Quote a value only to make a literal that would otherwise parse as a
list (a description starting with `[`). Skills are unaffected by any of this —
they are symlinked and never parsed.

## Translation

| Canonical | Claude `~/.claude/agents/<name>.md` | OpenCode `~/.config/opencode/agents/<name>.md` |
|---|---|---|
| `name` | `name:` verbatim | filename only — the id is the stem, so no key |
| `description` | verbatim | verbatim |
| — | — | `mode: subagent`, always |
| `tools` list | comma-joined `tools:` | boolean map: `<id>: false` for every mapped id **not** listed |
| `tools` omitted | key omitted (inherits all) | key omitted |
| `model` | verbatim | **omitted** — see lossy cases |
| `permission: read-only` | with no `tools`: synthesizes `tools: Read, Grep, Glob, WebFetch, WebSearch` | `permission: {edit: deny, bash: deny, webfetch: allow}` |
| `permission: safe` | nothing emitted (Claude's default) | `{edit: allow, bash: ask, webfetch: allow}` |
| `permission: full` | nothing emitted | `{edit: allow, bash: allow, webfetch: allow}` |

Tool-name map: `Read→read`, `Grep→grep`, `Glob→glob`, `Write→write`,
`Edit→edit`, `Bash→bash`, `WebFetch→webfetch`, `WebSearch→websearch`,
`TodoWrite→todowrite`. Claude-only names (`Task`, `NotebookEdit`, …) have no
OpenCode equivalent and are skipped rather than guessed at.

`permission: read-only` combined with `tools` containing `Write`, `Edit`,
`NotebookEdit`, or `Bash` is a generation error — the two would contradict.

## Lossy cases

These are deliberate, and the reason the table above is the contract:

- **Model tier is dropped on OpenCode.** OpenCode model ids are
  provider-qualified (`anthropic/claude-…`), which makes them machine-local;
  the subagent falls back to OpenCode's configured default model.
- **`permission` is dropped on Claude for `safe` and `full`.** Both map onto
  Claude's own defaults, and this layer never emits permission-bypass settings.
- **On OpenCode the two tool controls intersect.** A `tools:` map entry of
  `false` wins over a permission tier that would have allowed it — `explore`
  gets `webfetch: allow` from `read-only` but `webfetch: false` from its tool
  list, so it cannot fetch. That is the intended narrower behavior.

## Not projected

- **Codex** has no stable subagent file format; `agents_link` prints an INFO
  line rather than writing a guess.
- **Cursor** has a `~/.cursor/agents` directory whose format is unverified in
  the installed build. Left unmanaged, also reported as INFO.

## Adding one

Write `agents/subagents/<name>.md` following the schema, then:

```bash
bin/agents_link all           # regenerate every projection
bin/agents_link --check all   # confirm each row is OK
```
