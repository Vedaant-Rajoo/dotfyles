# Shared AI harness configuration

This directory is the source of truth for behavior shared by Claude Code, Codex,
OpenCode, and Cursor Agent:

- `agents/AGENTS.md` contains platform-neutral standing rules;
- `agents/skills/` uses the common `SKILL.md` directory format;
- `agents/subagents/` holds one canonical file per subagent — see
  [subagents/README.md](subagents/README.md);
- `agents/hooks/manifest.json` records the portable hook intersection, with
  commands under `agents/hooks/scripts/`.

The repository root's `AGENTS.md` is a symlink to `agents/AGENTS.md`, so tools
that look for standing rules beside the project root find the same bytes.

`bin/agents_link all` projects that core into each installed harness. It uses
native global rule files for Claude, Codex, and OpenCode; installs each shared
skill additively without replacing harness-native skills; and generates Cursor's
rule and hook files.

## Rules and skills are symlinked

Rules and skills are the same bytes everywhere, so they are symlinked — a skill
written into `~/.claude/skills/` physically lands in `agents/skills/` through the
link chain and is instantly shared with every other harness as a reviewable
diff. `~/.agents/` is the cross-tool convention: Codex and OpenCode scan
`~/.agents/skills` natively, `~/.agents/AGENTS.md` links to the same shared
rules, and `npx skills --global` installs there. Cursor resolves skills from an
explicit user-scope list — `~/.cursor/skills`, `~/.agents/skills`,
`~/.claude/skills`, `~/.codex/skills` — independent of project location, so it
is the one dimension where Cursor has no caveat at all.

## The Cursor caveats

Cursor is the exception that needs explaining. It has no global rules file — it
finds rules by walking up from the workspace directory, reading
`.cursor/rules/**/*.mdc` and `AGENTS.md` at every ancestor. So `agents_link`
generates `~/.cursor/rules/agents.mdc` with `alwaysApply: true`, which Cursor
reaches because `$HOME` is an ancestor of anything below it. **That covers every
project under your home directory and nothing outside it** — a repo at
`/opt/work/thing` gets no shared rules, silently. The conformance report states
that limit rather than claiming global coverage. Cursor also cannot take shared
subagents: its CLI reads them only from a workspace `.cursor/agents`, never from
`~/.cursor/agents`, so projecting there would fail with no error at all.

Two more gotchas worth knowing. Cursor's headless CLI fires only
`workspaceOpen`, `sessionStart`, and `sessionEnd` — **not** `stop` — so the
portable stop hook is projected to both `stop` and `sessionEnd`, and
`sessionEnd` is what actually runs outside the editor. Cursor also reads hooks
from `~/.claude/settings.json` as well as `~/.cursor/hooks.json`, which looks
like it should double-fire; measured, it does not, because `stop` fires from
neither channel headless. And do not export `XDG_CONFIG_HOME=~/.config` —
tempting, since this repo lives there — because Cursor would silently move its
config directory to `~/.config/cursor` and orphan `cli-config.json` and
`permissions.json`.

## Subagents are translated, not linked

Subagents cannot be symlinked, because Claude and OpenCode disagree about the
frontmatter. `bin/agents_render` translates each canonical file instead, and
`agents_link` writes the result to `claude/agents/` and `opencode/agents/` —
both of which are live harness directories in this working tree. Those generated
files are untracked and carry a `generated by bin/agents_link` header; edit
`agents/subagents/<name>.md` and re-run `bin/agents_link all`. Codex has no
stable subagent format, while Cursor supports subagents only in a workspace
`.cursor/agents`; neither has a user-global projection, so both are reported as
not applicable rather than guessed at. Model tiers are dropped on OpenCode (its
model ids are machine-local) — the full translation contract and its lossy cases
are documented in [subagents/README.md](subagents/README.md).

## Adopting a skill installed from outside

`npx skills add --global` writes a real directory into `~/.agents/skills/<name>`.
It works immediately but only on this machine, so `bin/agents_link --check`
reports it as unmanaged. Promote it:

```bash
bin/agents_link adopt --dry-run <name>   # show what would move
bin/agents_link adopt <name>             # move into agents/skills, relink, reproject
```

The directory is moved into `agents/skills/<name>` and linked back where it was.
Nothing is committed: adopted files come from outside this repository, so read
them before `git add`, and never let credentials land under `agents/`.

## Conformance

Run the read-only deterministic wiring checks at any time:

```bash
bin/agents_link --check all
bin/agents_conform
```

If the link check reports drift, `bin/agents_link all` is the reconciliation
command; it mutates projections and is not part of read-only verification.

Behavioral checks use real model calls and are deliberately opt-in:

```bash
bin/agents_conform --live           # rules + supported hooks
bin/agents_conform --live --skills  # also test skill discovery/invocation
```

The static tier exits non-zero on drift. It also validates
`agents/hooks/manifest.json` directly — shape, portable events, executable
commands — checks that Claude's
tracked settings really run every hook the manifest calls portable, and requires
each `agents/skills/*/SKILL.md` to declare a `name:` matching its directory. The
live tier prints a scorecard and is informational by default because model
obedience is probabilistic; set `AGENTS_LIVE_GATE=1` only when a failing canary
should fail automation. A skill joins the live tier by publishing a
`SKILL-CHECK <name>` contract line in its own `SKILL.md`.
